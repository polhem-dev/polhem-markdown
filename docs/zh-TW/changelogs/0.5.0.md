# Polhem.Markdown 0.5.0 — 發佈說明

[English](../../en/changelogs/0.5.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[0.5.0]` 條目的詳細內容。

這一版是給要處理文字內容的宿主：Avalonia 編輯器公開選取範圍、取代範圍、標示範圍，並提供搜尋與取代；兩個檢視器都可以在
程式碼區塊加上宿主自己的按鈕；核心套件可以依檢視器的安全政策把文字輸出成 HTML。編輯器的新成員只在 Avalonia 套件，
Blazor 編輯器尚未提供。

沒有任何公開成員被移除或變更。各類應用需要留意的項目：

- **使用編輯器的 Avalonia 應用**：Ctrl+F（⌘F）改為打開編輯器自己的搜尋列，不再是 AvaloniaEdit 的搜尋面板；
  Ctrl+H（⌥⌘F）打開含取代列的搜尋列（[編輯器的搜尋列取代 AvaloniaEdit 的搜尋面板](#編輯器的搜尋列取代-avaloniaedit-的搜尋面板)）。
- **繫結編輯器 `Markdown` 的 Avalonia 應用**：一組變更只在結束時通知一次
  （[`Markdown` 每組變更只通知一次](#markdown-每組變更只通知一次)）。
- **翻譯搜尋列（`FindBarLabels`）的 Avalonia 應用**：`MarkdownFindBarItem` 為編輯器的搜尋列新增項目
  （[新的搜尋列項目](#新的搜尋列項目)）。

Blazor 檢視器的標記與 `--pmd-*` CSS 變數都沒有改變。

## 新功能

### Avalonia 編輯器的選取範圍與範圍取代

Avalonia 的 `MarkdownEditor` 可以讀取選取範圍（`SelectionStart`、`SelectionLength`、`SelectedText`）、以程式碼選取
一個範圍並捲到看得見的位置（`Select`），並在游標或選取範圍移動時觸發一次 `SelectionChanged`
（[#95](https://github.com/polhem-dev/polhem-markdown/issues/95)）。

`Replace(start, length, text)` 取代一個範圍，`Replace(IEnumerable<MarkdownReplacement>)` 取代多個範圍，offset 都以
取代前的文字為準。兩者都只算一個復原步驟，保留之前的復原紀錄，游標與選取範圍的移動方式與打字相同。範圍重疊，或在同一個
offset 插入兩次，會在任何變更之前擲出 `ArgumentException`。`Replace` 對唯讀編輯器也會改變文字（與設定 `Markdown`
相同），且不會捲動。`MarkdownReplacement` 位於核心套件。

### Avalonia 編輯器的範圍標示與文字位置

`AddMark(start, length, style, brush, owner)` 在原文的某個範圍上畫出標示：背景、底線或刪除線
（`MarkdownRangeMarkStyle`），畫在選取範圍底下，與語法顏色互不影響
（[#96](https://github.com/polhem-dev/polhem-markdown/issues/96)）。回傳的 `MarkdownRangeMark` 跟著編輯移動：
在範圍內輸入的文字屬於範圍，在範圍邊緣插入的文字則不屬於；範圍內的文字全部刪除時，標示會被移除（`IsRemoved`）。
`RemoveMark`、`ClearMarks()`、`ClearMarks(owner)` 移除標示，`Marks` 列出所有標示。設定 `Markdown` 會移除所有標示。

`GetTextBounds(start, length)` 取得一個範圍（length 為 0 時是游標位置）在編輯器中的位置；範圍沒有排版時（捲出畫面、
或編輯器沒有顯示）回傳 `null`。`ViewChanged` 在位置可能改變時通知，宿主可以讓彈出視窗一直留在文字旁。範例程式以這兩者
用 diff 預覽一項修改，並附上接受與拒絕按鈕。

### Avalonia 編輯器的搜尋與取代

Ctrl+F（⌘F）在編輯器的原文上打開搜尋列，可選擇大小寫相符、全字相符與正規表示式（`MarkdownFindOptions`）；
Ctrl+H（⌥⌘F）打開含取代列的搜尋列（[#97](https://github.com/polhem-dev/polhem-markdown/issues/97)）。所有相符處都會
標示，F3 與 Shift+F3 逐一移動，Escape 關閉搜尋列。全部取代只算一個復原步驟；唯讀編輯器只能搜尋。

從程式碼操作：`OpenFind`、`OpenReplace`、`CloseFind`、`IsFindOpen`、`IsReplaceOpen`、`Find`、`FindNext`、
`FindPrevious`、`FindMatchCount`、`CurrentFindMatch`、`ReplaceCurrentMatch`、`ReplaceAllMatches`。
`FindMatchBrush`、`FindCurrentMatchBrush`、`FindBarLabels` 的用法與檢視器相同。正規表示式的比對逾時為一秒，取代文字
可使用 `$1` 與 `${name}`；無效的運算式會讓輸入框顯示紅框，`Find` 則擲出 `ArgumentException`。`HandleFindShortcuts`
設為 `false` 時按鍵交給宿主，由宿主從自己的選單打開搜尋列。

### 程式碼區塊上的宿主按鈕

兩個檢視器都接受 `CodeBlockActions`（元素為 `MarkdownCodeBlockAction`），每個動作顯示為一個按鈕，位於語言標籤與複製
按鈕之間（[#99](https://github.com/polhem-dev/polhem-markdown/issues/99)）。動作包含標籤、可選的圖示（`IconPath`，
24×24 範圍內的 SVG path 資料；有圖示時標籤成為提示文字與無障礙名稱）、可選的逐區塊 `IsVisible` 判斷，以及要執行的工作；
工作會收到區塊的程式碼與語言（`MarkdownCodeBlock`），可以是同步的，也可以回傳 `Task`。`IsVisible` 依賴的狀態改變時，
呼叫 `RefreshCodeBlockActions`（Avalonia）或 `RefreshCodeBlockActionsAsync`（Blazor）重新判斷。按鈕與複製按鈕一樣
一直顯示，顏色也相同；沒有新增 CSS 變數。

動作擲出的例外不會被檢視器攔下。

### 把文字輸出成 HTML

`Polhem.Markdown` 的 `MarkdownHtml` 從檢視器的 model、依相同的 `MarkdownOptions` 與安全政策把文字輸出成 HTML
（[#98](https://github.com/polhem-dev/polhem-markdown/issues/98)）：

- `ToPage` 輸出外觀與檢視器一致的獨立網頁，可存成檔案，或在 web view 中列印。
- `ToFragment` 輸出一個 `<div class="pmd">`，放進宿主自己的網頁，以 `MarkdownHtml.StyleSheet` 套上樣式。
- 程式碼上色、Mermaid 圖表（SVG）與數學式（MathML）都是 Blazor 檢視器畫出的靜態標記，不帶 script。複製按鈕、動作按鈕
  與放大按鈕不會輸出。
- stylesheet 就是 Blazor 檢視器的那一份，使用相同的 `--pmd-*` 變數，所以佈景主題的對應也適用於輸出的網頁。
  `MarkdownHtmlOptions.StyleSheet` 在其後加上 CSS，`Title` 與 `Language` 設定網頁的標題與 `lang`。
- 圖片預設維持連結；宿主從 `MarkdownHtmlOptions.ImageContent` 回傳位元組（`MarkdownImageContent`，媒體類型須為
  `image/*`）時，以 `data:` URI 嵌入。套件本身不讀取檔案或網路，被安全政策拒絕的圖片也不會詢問宿主。

## 行為變更

### 編輯器的搜尋列取代 AvaloniaEdit 的搜尋面板

在 Avalonia 的 `MarkdownEditor` 中，Ctrl+F（⌘F）原本打開 AvaloniaEdit 的搜尋面板，現在改為打開編輯器自己的搜尋列，
AvaloniaEdit 的面板不再出現，即使 `HandleFindShortcuts` 設為 `false` 也一樣。`HandleFindShortcuts` 開啟時，編輯器會把
搜尋與取代的按鍵標為已處理，有相符處時 F3 也是。

**該怎麼處理**：除非應用程式在編輯器中綁定了這些按鍵，否則不需處理。若有，把 `HandleFindShortcuts` 設為 `false`，
從自己的命令呼叫 `OpenFind` 或 `OpenReplace`。

### `Markdown` 每組變更只通知一次

Avalonia 編輯器原本在一組變更（例如復原多個編輯）中的每一項變更之後都更新 `Markdown`，繫結會看到改到一半的文字。
現在只在這組變更結束時設定一次 `Markdown`。

**該怎麼處理**：不需處理。讀取 `Markdown` 的宿主看到的最終文字相同，只是更新次數較少。

### 新的搜尋列項目

`MarkdownFindBarItem` 新增 `WholeWord`、`RegularExpression`、`ReplaceField`、`Replace`、`ReplaceAll`，只有編輯器的
搜尋列會顯示。檢視器的搜尋列不變。

**該怎麼處理**：翻譯編輯器搜尋列的 `FindBarLabels` 函式要為這些項目回傳標籤；對它們回傳 `null` 則沿用英文標籤。
