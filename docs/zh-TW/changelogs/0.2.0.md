# Polhem.Markdown 0.2.0 — 發佈說明

[English](../../en/changelogs/0.2.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[0.2.0]` 條目的詳細內容。

檢視器現在能呈現 README 或 AI 回覆中大部分 GitHub 會呈現的內容：Mermaid 圖、程式碼上色、圖片、數學公式、註腳、警示，
以及 README 常用的 raw HTML，而且在 Avalonia 與 Blazor 上呈現方式相同。Avalonia 套件新增 `MarkdownEditor`，
依檢視器讀取 Markdown 的方式為原始碼上色，並可與檢視器同步捲動。本版也修正一個崩潰：大量巢狀的行內語法會讓堆疊溢位，
使顯示它的應用程式結束。

沒有任何公開成員被移除或變更。各類應用需要留意的項目：

- **所有應用**：圖片預設會載入，白名單內的 raw HTML 改為呈現，不再以文字顯示
  （[圖片預設會載入](#圖片預設會載入)、[白名單內的 raw HTML 改為呈現](#白名單內的-raw-html-改為呈現)）。
- **允許 `file` 連結 scheme 的應用**：[沒有 scheme 的目標視為相對參照](#沒有-scheme-的目標視為相對參照)。
- **設有 Content Security Policy 的 Blazor 應用**：[Blazor 檢視器會載入模組](#blazor-檢視器會載入模組)。
- **Avalonia 應用**：[新增的相依套件](#polhemmarkdownavalonia-新增的相依套件)。
- **對應 `--pmd-*` 變數的 Blazor 佈景主題**：警示、程式碼 token 與數學公式有新變數
  （[GitHub 警示](#github-警示)、[程式碼上色](#程式碼上色)、[數學公式](#數學公式)）。

## 新功能與變更

### Mermaid 圖

內容為流程圖（`flowchart` / `graph`，四個方向皆可）或循序圖的 ` ```mermaid ` 區塊，由 `Polhem.Markdown` 排版、
兩個檢視器繪製，不執行指令碼。文字大小依字元估算，因此兩個檢視器拿到相同的座標。退回規則是全有或全無：其他圖表類型、
超出子集的敘述（subgraph、樣式、迴圈、activation…）或超過上限（200 個節點、400 條連線、40 個參與者）的圖，
維持程式碼區塊。圖會置中，並縮小到檢視器的寬度。`MarkdownOptions.RenderMermaidDiagrams` 預設為 `true`，可用來關閉。

圖使用既有的程式碼背景色、分隔線色與文字色，沒有新增變數。

### 程式碼上色

程式碼區塊依圍欄標示的語言上色：C#、JSON、SQL、shell、PowerShell、JavaScript/TypeScript、Python、XML/HTML、Razor、
YAML 與 CSS。掃描器為本套件自行撰寫，不用正規表示式、不增加相依，執行時間為線性。縮排程式碼區塊與未知語言維持純文字，
與 GitHub 相同。

- Avalonia：`CodeKeywordBrush`、`CodeStringBrush`、`CodeCommentBrush`、`CodeConstantBrush`、`CodeTagBrush` 與
  `CodePropertyBrush`。變更筆刷會直接重新上色，不需重建。
- Blazor：`--pmd-code-keyword`、`--pmd-code-string`、`--pmd-code-comment`、`--pmd-code-constant`、`--pmd-code-tag` 與
  `--pmd-code-property`。

### 圖片

圖片來源（原文或依 `BaseUri` 解析後）的 scheme 在 `MarkdownOptions.AllowedImageSchemes`（新增，預設 `https`）內時會顯示；
其他圖片和以前一樣顯示替代文字。不支援 `data:` URI。

- Blazor 輸出 `<img loading="lazy" referrerpolicy="no-referrer">`，只縮小、不放大。
- Avalonia 在圖片載入前、以及載入失敗後顯示替代文字。它自行載入 `http`/`https` 與 `file`，每張最多 10 MB，並在每個檢視器內
  快取；`MarkdownViewer.ImageLoader`（新增）可替換載入方式，用於驗證、快取或 proxy。
- Avalonia 只畫經 `https`、來自 `MarkdownViewer.TrustedSvgHosts`（新增，預設為 `img.shields.io` 等徽章服務）主機的 SVG，
  或 GitHub workflow 徽章，因為惡意的 SVG 可以耗盡繪製器的資源
  （[ADR-001](../../../maintainers/adr/adr-001-svg-from-trusted-hosts.md)）。其他 SVG 顯示替代文字，所以專案自家網站的
  SVG 標誌需要把該主機加進清單。Blazor 以 `<img>` 顯示所有允許的 SVG，其中的指令碼不會執行。

### 數學公式

與 GitHub 寫法相同的數學公式（`$…$`、`` $`…`$ ``、`$$…$$` 與 ` ```math ` 區塊）以 LaTeX 子集呈現：分數、根號、上下標、
`\left … \right`、矩陣與 `cases`、`\text`、重音符號與間距
（[ADR-002](../../../maintainers/adr/adr-002-math-one-structure-two-layouts.md)）。單一個 `$` 旁邊是空白時不開始也不結束
公式，所以價格維持文字。超出子集的公式以程式碼顯示原文。

- Blazor 輸出 MathML 交給瀏覽器排版，字型以 `--pmd-math-font`（新增）設定。字型有數學表時，括號才會隨內容放大。
- Avalonia 以檢視器的字型自行排版。

### 註腳

註腳依讀者讀到的順序編號，列在文末並附返回連結。參照未定義的註腳時依原文顯示。

### GitHub 警示

以 `[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]` 或 `[!CAUTION]` 開頭的引用會成為警示，附圖示與英文標題，與 GitHub 相同。
其他標記維持一般引用。

- Avalonia：`AlertNoteBrush`、`AlertTipBrush`、`AlertImportantBrush`、`AlertWarningBrush` 與 `AlertCautionBrush`。
- Blazor：`--pmd-alert-note`、`--pmd-alert-tip`、`--pmd-alert-important`、`--pmd-alert-warning` 與 `--pmd-alert-caution`。

### raw HTML 經白名單轉換

README 常用的元素會成為模型的節點：`img`、`a`、`br`、`b`、`strong`、`i`、`em`、`code`、`sup`、`sub`、`kbd`、置中或靠右對齊的
`p` 與 `div`、`details` 與 `summary`，以及依色彩配置挑選 `source` 的 `picture`。`href` 與 `src` 會經過連結與圖片的政策檢查。
其他元素去掉標籤、保留內容；`script`、`style`、`iframe` 等元素的內容則丟棄。任何 HTML 都不會以標記形式交給檢視器。

只是看起來像標籤的文字（`List<string>`），以及在段落內沒有成對的標籤，依原文顯示，因為文章提到標籤名稱的情況遠多於
真的留下未關閉的標籤。

### 相對連結與圖片

`MarkdownOptions.BaseUri`（新增，絕對 URI）依標準 URI 規則解析相對連結與圖片，解析結果仍要經過 scheme 檢查。
沒有設定時，相對連結維持文字。

### 連到標題與註腳

標題的 id 與 GitHub 相同，連到同一份文字內 `#id` 的連結會讓檢視器捲動到該標題或註腳。這類連結不會觸發
`LinkActivated` / `OnLinkActivated`。Blazor 檢視器不把 id 寫成 HTML 的 `id`，所以不會與宿主頁面或另一個檢視器衝突。

### 刪除線、任務清單、emoji 與 front matter

`~~文字~~` 顯示刪除線；`- [ ]` 與 `- [x]` 顯示核取方塊，兩個檢視器都以連結色與分隔線色自行繪製，各處外觀一致。
`:smile:` 這類 emoji 短碼會轉成 emoji。文字開頭的 YAML front matter 會隱藏。

### Avalonia 檢視器的粗體中日韓文字

受 Avalonia 重用 fallback 字型的方式影響，Avalonia 檢視器的粗體中日韓文字可能顯示為一般粗細，或讓整行之後都變粗體。
`MarkdownViewer.CjkFontFamily`（新增，預設 `null`）指定繪製中日韓文字的字型家族，例如
`PingFang TC, Microsoft JhengHei UI, Noto Sans CJK TC`；設定後檢視器以該字型繪製中日韓文字，並在繪製前載入較粗的字重。

### `MarkdownEditor`

`Polhem.Markdown.Avalonia` 新增 `MarkdownEditor`，建構在 AvaloniaEdit 核心上的 Markdown 原始碼編輯器
（[#37](https://github.com/polhem-dev/polhem-markdown/issues/37)）：

- 行號、自動換行、復原與重做、搜尋（Ctrl+F）。
- 為標記、標題、強調、程式碼、連結、URL、raw HTML 與公式上色；程式碼區塊的上色與檢視器相同，筆刷名稱也相同。
- `ApplyFormat(MarkdownFormat)` 對選取範圍套用或移除格式，一次復原即可還原。`MarkdownFormat` 是 `Polhem.Markdown` 新增的
  列舉：`Bold`、`Italic`、`Strikethrough`、`InlineCode`、`Link`、`Heading1` 到 `Heading3`、`BulletList`、`NumberedList`、
  `TaskList`、`Quote` 與 `CodeBlock`。Ctrl（macOS 為 Cmd）加 B、I、K、E 分別套用粗體、斜體、連結與行內程式碼。
- Enter 延續清單，在空白項目上則結束清單；Tab 與 Shift+Tab 調整清單項目的層級。
- `Markdown` 預設雙向繫結。原始碼中的連結無法從編輯器開啟，因為那會繞過 scheme 檢查。
- 自帶佈景主題資源，在 Fluent、Simple、Semi 或其他宿主佈景主題下都能使用。

公開 API 不含任何 AvaloniaEdit 型別。

### 讓編輯器與檢視器同步

- `MarkdownViewer.GetVerticalOffset(int)` 與 `GetSourceOffset(double)` 在原始碼位置與檢視器的垂直位置之間換算。
- 按住命令鍵（Ctrl，macOS 為 Cmd）點選時觸發 `MarkdownViewer.SourceRequested`；沒有處理該事件的處理常式時，
  按住命令鍵點選的行為與以前相同。
- `MarkdownEditor.FirstVisibleSourceOffset` 與 `ScrollToSourceOffset(int)` 在編輯器這一側做同樣的事。

### Avalonia 檢視器的部分重建

`Markdown` 變更時，Avalonia 檢視器現在保留從開頭與從結尾比對相符的區塊，只重建中間的部分。在 66 個區塊的文字最前面插入
一個段落，重建的區塊從 67 個（25 ms）降為 1 個（3 ms）。保留下來的區塊會維持狀態，例如選取範圍或展開的區段。
從尾端增長的回覆行為與以前相同。

## 行為變更

### 圖片預設會載入

0.1.0 一律以替代文字顯示圖片。現在會載入 `https` 的圖片，等於告訴圖片所在的伺服器這份文字被檢視過。

**怎麼處理**：要維持 0.1.0 的行為，清空這個集合：

```csharp
options.AllowedImageSchemes.Clear();
```

### 白名單內的 raw HTML 改為呈現

0.1.0 把所有 raw HTML 依原文以文字顯示。現在白名單內的元素會呈現，其他元素去掉標籤，`script`、`style` 等元素的內容則丟棄。
除非宿主依賴看到 HTML 原文，否則不需處理。

### 沒有 scheme 的目標視為相對參照

只有寫出 scheme 的連結目標才算絕對 URI。.NET 會把 `/etc/passwd` 這類根路徑讀成 `file:///etc/passwd`，所以允許 `file`
scheme 的宿主原本會從它得到一個本機檔案連結。現在它和其他相對參照一樣依 `BaseUri` 解析，沒有設定時顯示為文字。

**怎麼處理**：`AllowedLinkSchemes` 含 `file` 時，要連到本機檔案請寫成 `file:///…`。

### Blazor 檢視器會載入模組

Blazor `MarkdownViewer` 現在實作 `IAsyncDisposable`，並在第一次點選文件內連結時載入一個小模組 `polhem-markdown.js`，
用來捲動到目標。

**怎麼處理**：設有 Content Security Policy 的頁面必須允許自身來源的指令碼。沒有這個模組時點選不會有反應，其他功能不受影響。

### `Polhem.Markdown.Avalonia` 新增的相依套件

`Polhem.Markdown.Avalonia` 新增相依：

- `Svg.Skia` 5.1.1，用於 SVG 圖片。這是最後一個建構在 SkiaSharp 3（Avalonia 12 使用的版本）上的版本。Native AOT 下可以運作，
  但 `Svg.Model` 會回報裁剪警告（IL2104），把警告視為錯誤的應用程式需要抑制它。
- `Avalonia.AvaloniaEdit` 12.0.0，用於編輯器，只用其核心。只用檢視器的應用程式，Native AOT 執行檔與之前相同；
  非 AOT 會多帶一個不會載入的 `AvaloniaEdit.dll`（約 630 KB）。

## 修正

- 大量巢狀的行內語法（例如約一萬個未閉合的 `[`，或包住一個字的兩萬個 `*`）會讓堆疊溢位，使以檢視器顯示它的應用程式結束。
  超過 32 層的行內巢狀現在以原文顯示剩下的部分（[#41](https://github.com/polhem-dev/polhem-markdown/pull/41)）。
- 未閉合的 `[` 原本會消失（`a [b c` 顯示為 `a b c`），現在依原文顯示，與 GitHub 相同。
- Avalonia 檢視器會截掉每個程式碼區塊的最後一行。
