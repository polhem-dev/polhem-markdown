# Polhem.Markdown 0.5.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.5.0.md)

This file holds the details behind the `[0.5.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This version is for hosts that work on the text: the Avalonia editor exposes its selection, replaces ranges, marks
ranges and finds and replaces; both viewers take a host's own buttons on code blocks; and the core package writes a
text as HTML under the viewers' safety policy. The editor's new members are on the Avalonia package only; the Blazor
editor does not have them yet.

No public member is removed or changed. What each kind of application has to look at:

- **Avalonia applications that use the editor**: Ctrl+F (⌘F) now opens the editor's own find bar instead of
  AvaloniaEdit's search panel, and Ctrl+H (⌥⌘F) opens it with a replace row
  ([The editor's find bar replaces AvaloniaEdit's search panel](#the-editors-find-bar-replaces-avaloniaedits-search-panel)).
- **Avalonia applications that bind the editor's `Markdown`**: a group of changes is reported once, when it ends
  ([`Markdown` is reported once per group of changes](#markdown-is-reported-once-per-group-of-changes)).
- **Avalonia applications that translate the find bar (`FindBarLabels`)**: `MarkdownFindBarItem` has new items for the
  editor's bar ([New find bar items](#new-find-bar-items)).

The Blazor viewer's markup and its `--pmd-*` CSS variables are unchanged.

## New features

### Selection and range replacement in the Avalonia editor

The Avalonia `MarkdownEditor` reads the selection (`SelectionStart`, `SelectionLength`, `SelectedText`), selects a
range from code and scrolls it into view (`Select`), and raises `SelectionChanged` once when the caret or the selection
moves ([#95](https://github.com/polhem-dev/polhem-markdown/issues/95)).

`Replace(start, length, text)` replaces one range, and `Replace(IEnumerable<MarkdownReplacement>)` several, with
offsets in the text before any of them. Either is one step to undo, keeps the history before it, and moves the caret
and the selection as typing would. Overlapping ranges, and two insertions at the same offset, are rejected with
`ArgumentException` before anything changes. `Replace` also changes a read-only editor's text, as setting `Markdown`
does, and does not scroll. `MarkdownReplacement` is in the core package.

### Range marks and text bounds in the Avalonia editor

`AddMark(start, length, style, brush, owner)` draws a mark over a range of the source: a background, an underline or a
strikethrough (`MarkdownRangeMarkStyle`), under the selection and apart from the syntax colors
([#96](https://github.com/polhem-dev/polhem-markdown/issues/96)). The returned `MarkdownRangeMark` follows the edits:
text typed inside the range is part of it, text inserted at its edges is not, and a mark whose text is all deleted is
removed (`IsRemoved`). `RemoveMark`, `ClearMarks()` and `ClearMarks(owner)` remove marks, and `Marks` lists them.
Setting `Markdown` removes every mark.

`GetTextBounds(start, length)` gives where a range, or a caret's place for length 0, is in the editor, or `null` when
it is not laid out (scrolled out of view, or the editor not shown). `ViewChanged` tells when that may have moved, so a
host can keep a popup next to the text. The gallery uses both to preview a change as a diff with Accept and Reject
buttons.

### Find and replace in the Avalonia editor

Ctrl+F (⌘F) opens a find bar over the editor's source, with options for case, whole words and regular expressions
(`MarkdownFindOptions`); Ctrl+H (⌥⌘F) opens it with a replace row
([#97](https://github.com/polhem-dev/polhem-markdown/issues/97)). Every match is highlighted, F3 and Shift+F3 step
through them, and Escape closes the bar. Replacing every match is one step to undo; a read-only editor opens find only.

From code: `OpenFind`, `OpenReplace`, `CloseFind`, `IsFindOpen`, `IsReplaceOpen`, `Find`, `FindNext`, `FindPrevious`,
`FindMatchCount`, `CurrentFindMatch`, `ReplaceCurrentMatch` and `ReplaceAllMatches`. `FindMatchBrush`,
`FindCurrentMatchBrush` and `FindBarLabels` work as on the viewer. A regular expression has a one-second match timeout
and takes `$1` and `${name}` in the replacement; an invalid one gives the field a red border, and `Find` throws
`ArgumentException`. `HandleFindShortcuts` set to `false` leaves the keys to the host, which opens the bar from its own
menu.

### A host's own buttons on code blocks

Both viewers take `CodeBlockActions`, a list of `MarkdownCodeBlockAction`, and show each as a button between the
language label and the copy button ([#99](https://github.com/polhem-dev/polhem-markdown/issues/99)). An action has a
label, an optional icon (`IconPath`, SVG path data in a 24×24 box, for which the label becomes the tooltip and the
accessible name), an optional `IsVisible` test per block, and the work to do, which receives the block's code and
language (`MarkdownCodeBlock`), synchronous or returning a `Task`. `RefreshCodeBlockActions` (Avalonia) and
`RefreshCodeBlockActionsAsync` (Blazor) ask `IsVisible` again when what it depends on changes. The buttons are always
shown, as the copy button is, and take the same colors; no CSS variable is added.

An exception thrown by an action is not caught by the viewer.

### Writing a text as HTML

`MarkdownHtml`, in `Polhem.Markdown`, writes a text as HTML from the viewers' model, under the same `MarkdownOptions`
and safety policy ([#98](https://github.com/polhem-dev/polhem-markdown/issues/98)):

- `ToPage` writes a standalone page with the viewers' look, to save as a file or to print from a web view.
- `ToFragment` writes one `<div class="pmd">` for a host's own page, styled by `MarkdownHtml.StyleSheet`.
- Code highlighting, Mermaid diagrams (SVG) and math (MathML) are the static markup the Blazor viewer draws, with no
  script. The copy button, the action buttons and the zoom button are left out.
- The stylesheet is the Blazor viewer's, with the same `--pmd-*` variables, so a theme's mapping also themes an
  exported page. `MarkdownHtmlOptions.StyleSheet` adds CSS after it, `Title` and `Language` set the page's title and
  `lang`.
- Images stay links, unless the host returns their bytes from `MarkdownHtmlOptions.ImageContent`
  (`MarkdownImageContent`, an `image/*` media type); they are then embedded as `data:` URIs. The package never reads
  files or the network, and the host is never asked for an image the policy refused.

## Changes in behaviour

### The editor's find bar replaces AvaloniaEdit's search panel

In the Avalonia `MarkdownEditor`, Ctrl+F (⌘F) used to open AvaloniaEdit's search panel. It now opens the editor's own
find bar, and AvaloniaEdit's panel no longer opens, even with `HandleFindShortcuts` set to `false`. While
`HandleFindShortcuts` is on, the editor marks the find and replace keys handled, and F3 while there are matches.

**What to do**: nothing, unless your application binds these keys in the editor. Then set `HandleFindShortcuts` to
`false` and call `OpenFind` or `OpenReplace` from your own command.

### `Markdown` is reported once per group of changes

The Avalonia editor used to push `Markdown` after each change inside a group of changes, such as an undo of several
edits, so a binding saw the text halfway through. It now sets `Markdown` once when the group ends.

**What to do**: nothing. A host that reads `Markdown` sees the same final text, through fewer updates.

### New find bar items

`MarkdownFindBarItem` adds `WholeWord`, `RegularExpression`, `ReplaceField`, `Replace` and `ReplaceAll`, which only the
editor's bar shows. The viewer's bar is unchanged.

**What to do**: a `FindBarLabels` function that translates the editor's bar returns a label for these items. One that
returns `null` for them keeps the English labels.
