# Polhem.Markdown 0.3.1 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.3.1.md)

This file holds the details behind the `[0.3.1]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

`Polhem.Markdown.Blazor` is now checked under trimming, the way a Blazor WebAssembly app is published. No public member
is added, removed or changed, and the viewer and the editor look and behave as in 0.3.0. `Polhem.Markdown` and
`Polhem.Markdown.Avalonia` ship under the new version without changes of their own.

What each kind of application has to look at:

- **Blazor apps that trim with `TrimMode=partial`**: this package is now trimmed too
  ([`Polhem.Markdown.Blazor` is marked trimmable](#polhemmarkdownblazor-is-marked-trimmable)).

## Changes

### `Polhem.Markdown.Blazor` is marked trimmable

The package is marked trim and AOT compatible (`IsAotCompatible`), as `Polhem.Markdown` already was, so the trim and AOT
analyzers run on every build of it. Its assembly now carries the trimmable mark: an app that trims only the assemblies
marked trimmable (`TrimMode=partial`) trims this one too, where 0.3.0 kept it whole. An app with `TrimMode=full`
trimmed it already.

The repository checks it with `samples/MarkdownGallery.Wasm`, the gallery on standalone Blazor WebAssembly. The `wasm`
job of Build CI publishes the sample with `TrimMode=full`, and every trim warning in this repository's assemblies or
in Markdig fails it ([#66](https://github.com/polhem-dev/polhem-markdown/pull/66)).

If something the package needs at run time is trimmed away in your app, open an issue with the publish settings you use.
