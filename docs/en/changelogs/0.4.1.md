# Polhem.Markdown 0.4.1 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.4.1.md)

This file holds the details behind the `[0.4.1]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

A fix to `IsStreaming`, which 0.4.0 added to both viewers. No public member is added, removed or changed, and a text that
is not streaming shows as in 0.4.0. All three packages ship under the new version; the change is in `Polhem.Markdown`,
which both viewers use to complete a streaming text.

What each kind of application has to look at:

- **Apps that set `IsStreaming`**: replies with display math on one line now show the rest of the reply as it will look
  once complete ([Text after one-line display math is completed](#text-after-one-line-display-math-is-completed)).

## Changes

### Text after one-line display math is completed

While `IsStreaming` is set, the viewers close the syntax the last block of the text leaves open, so a reply shows as it
will look once complete. In 0.4.0 that stopped as soon as the text held display math written on one line, such as
`$$x = 1$$`: the line was taken for the start of a math block, a block that never closed, so the text was treated as
ending inside it and nothing after it was completed. A link, an image, emphasis or a table's header row after the
formula showed its Markdown until the reply was complete. Display math across lines, with `$$` on lines of their own,
was not affected.

A `$$` line now starts a math block only when nothing follows the `$$` on it, as Markdig reads it. In the same way, a
line that starts with three backticks and has another backtick after them, a code span such as ```` ```x``` ````, no
longer stops the text after it from being completed
([#94](https://github.com/polhem-dev/polhem-markdown/pull/94)).
