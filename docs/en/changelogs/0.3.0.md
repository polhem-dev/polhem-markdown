# Polhem.Markdown 0.3.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.3.0.md)

This file holds the details behind the `[0.3.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

The Blazor package adds `MarkdownEditor`, so both front ends now have a source editor that colours Markdown the way the
viewers read it and keeps in step with a viewer. Both editors gain a toolbar above the text, like HackMD's, and the
Blazor editor gains the line numbers the Avalonia one has, so the two editors look and work the same. `MarkdownFormat`
gains images, tables and horizontal rules, and the editors a heading cycle.

No public member is removed or changed. What each kind of application has to look at:

- **Avalonia applications that use `MarkdownEditor`**: the editor now shows a toolbar, and Tab passes the editor
  itself by ([The Avalonia editor shows a toolbar](#the-avalonia-editor-shows-a-toolbar),
  [Tab passes the Avalonia editor by](#tab-passes-the-avalonia-editor-by)).
- **Code that switches over `MarkdownFormat`**: [three new values](#markdownformat-has-three-new-values).
- **Blazor applications with a Content Security Policy that use the editor**: the editor loads a module of the package
  ([`MarkdownEditor` for Blazor](#markdowneditor-for-blazor)).
- **Blazor themes that map the `--pmd-*` variables**: new variables for the editor
  ([`MarkdownEditor` for Blazor](#markdowneditor-for-blazor), [Toolbars](#toolbars-in-both-editors)).

## New features and changes

### `MarkdownEditor` for Blazor

`Polhem.Markdown.Blazor` adds `MarkdownEditor`, the Blazor counterpart of the Avalonia editor
([#51](https://github.com/polhem-dev/polhem-markdown/issues/51)):

- The text is typed into a native `<textarea>`, so input methods, on-screen keyboards and screen readers work as
  anywhere on the page. The colours are drawn on a layer behind it by the package's script module,
  `polhem-markdown-editor.js`, which the component loads itself.
- Colouring of markers, headings, emphasis, code, links, URLs, raw HTML and formulas, with fenced code highlighted as in
  the viewers. The scan runs a moment after typing stops and sends only the spans that changed.
- `Markdown` and `MarkdownChanged` bind with `@bind-Markdown`. Line breaks come back as the host's text used them.
- The editor keeps its own undo history (`UndoAsync`, `RedoAsync`, Ctrl+Z, Ctrl+Shift+Z and Ctrl+Y, and the browser's
  Edit menu), because the browsers' own does not survive the edits the editor makes itself.
- `ApplyFormatAsync(MarkdownFormat)` and the shortcuts (Ctrl, or Command on a Mac, with B, I, K and E) apply formats.
  Enter continues a list, and Tab and Shift+Tab move a list item in and out; Tab elsewhere moves the focus on.
- `IsReadOnly`, `WordWrap`, `FocusAsync`, `SetCaretOffsetAsync`, and `Class` and further attributes, such as an
  `aria-label`, for the textarea.
- It works under interactive server, WebAssembly and auto rendering. Rendered statically, it shows the text read-only.

The stylesheet is the viewer's, `polhem-markdown.css`. The editor uses `--pmd-code-font`, `--pmd-link` and the
`--pmd-code-*` token colours, and adds `--pmd-heading`, `--pmd-marker`, `--pmd-inline-code`, `--pmd-url`, `--pmd-math`,
`--pmd-selection` and `--pmd-caret`.

**What to do**: a page with a Content Security Policy must allow scripts from its own origin. Without the module the
textarea still edits the text, without colours, toolbar commands or line numbers.

### Toolbars in both editors

Both editors show a toolbar above the text ([#57](https://github.com/polhem-dev/polhem-markdown/issues/57),
[#58](https://github.com/polhem-dev/polhem-markdown/issues/58)): bold, italic, strikethrough; the heading cycle; inline
code, code block, quote; bulleted, numbered and task lists; link, image, table, horizontal rule; undo and redo. The two
toolbars have the same buttons, order and icons.

- `ShowToolbar`, `true` by default, hides it. A host with buttons of its own calls `ApplyFormat(Async)`,
  `CycleHeading(Async)`, `Undo(Async)` and `Redo(Async)` from them.
- `ToolbarLabels` (a `Func<MarkdownToolbarItem, string?>`) replaces the English labels, which are each button's tooltip
  and accessible name; `null` keeps the English one. The tooltip adds the shortcut for the platform (Ctrl+B or ⌘B).
  `MarkdownToolbarItem` is a new enumeration in `Polhem.Markdown` naming the buttons.
- A click keeps the focus and the selection in the text. The buttons are disabled while the editor is read-only, and
  undo and redo while there is no step to take.
- Tab reaches the toolbar once; the arrow keys, Home and End move between the buttons, and Escape goes back to the text.
- The icons are drawn for the package; no icon set is added.
- Avalonia: the buttons are the host theme's `Button`s, and `ToolbarBackground` and `ToolbarBorderBrush` set the
  toolbar's look.
- Blazor: `--pmd-toolbar-background`, `--pmd-toolbar-border` and `--pmd-toolbar-icon` set the toolbar's look. The
  editor's markup has a `.pmd-editor-body` element between the root and the textarea.

### Line numbers in the Blazor editor

`MarkdownEditor.ShowLineNumbers`, `true` by default as on Avalonia, numbers the lines in a gutter. A wrapped line has one
number. `--pmd-line-number` sets their colour. Typing in a 130,000-character, 5,000-line text takes about 36 ms per key
with numbers against 26 ms without; in a few hundred lines, about a millisecond.

### Images, tables, rules and a heading cycle

- `MarkdownFormat` gains `Image` (`![text](url)`, with the address selected), `Table` (a two-column table with the caret
  in its first header cell) and `HorizontalRule` (`---`). A table and a rule are inserted below the selection, with a
  blank line wherever text would otherwise touch them, and applying them again inserts another.
- `MarkdownEditor.CycleHeading()` (Avalonia) and `CycleHeadingAsync()` (Blazor) step the selected lines through heading
  levels 1, 2 and 3 and back to plain text.

### Keeping the Blazor editor and viewer in step

As on Avalonia since 0.2.0:

- `MarkdownViewer.ScrollToSourceOffsetAsync(int)`, and `FirstVisibleSourceOffset` with
  `FirstVisibleSourceOffsetChanged`, map between a source offset and the viewer's scroll position.
- `MarkdownViewer.OnSourceRequested` receives a click with Ctrl or Command, with the source offset of what was clicked
  (`MarkdownSourceRequestedEventArgs`).
- `MarkdownEditor.ScrollToSourceOffsetAsync(int)`, `FirstVisibleSourceOffset` and `FirstVisibleSourceOffsetChanged`
  do the same on the editor side.

## Changes in behaviour

### The Avalonia editor shows a toolbar

The Avalonia `MarkdownEditor` now shows the toolbar above the text, so an application that upgrades sees a new row in
its editor.

**What to do**: to keep the 0.2 look, turn it off:

```xml
<md:MarkdownEditor ShowToolbar="False" />
```

### Tab passes the Avalonia editor by

The editor itself is no longer a tab stop: Tab goes to the toolbar's first button, then to the text. `Focus()` still
moves the focus to the text, and without the toolbar Tab goes to the text as before.

### `MarkdownFormat` has three new values

`Image`, `Table` and `HorizontalRule` are added at the end. Code that maps every `MarkdownFormat` with a `switch`, such
as to a button of its own, gets three values it does not handle.
