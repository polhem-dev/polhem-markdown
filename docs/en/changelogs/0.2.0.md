# Polhem.Markdown 0.2.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.2.0.md)

This file holds the details behind the `[0.2.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

The viewers now render most of what GitHub renders in a README or an AI reply: Mermaid diagrams, highlighted code,
images, math, footnotes, alerts and the raw HTML README files use, each the same way in Avalonia and Blazor. The
Avalonia package adds `MarkdownEditor`, a source editor that colours Markdown as the viewers read it and can be kept in
step with a viewer. The release also fixes a crash: deeply nested inline syntax overflowed the stack and ended the
application showing it.

No public member is removed or changed. What each kind of application has to look at:

- **Every application**: images now load by default, and allowed raw HTML renders instead of showing as text
  ([Images load by default](#images-load-by-default), [Allowed raw HTML renders](#allowed-raw-html-renders)).
- **Applications that allow the `file` link scheme**: [A target without a scheme is a relative
  reference](#a-target-without-a-scheme-is-a-relative-reference).
- **Blazor applications with a Content Security Policy**: [The Blazor viewer loads a module](#the-blazor-viewer-loads-a-module).
- **Avalonia applications**: [New dependencies](#new-dependencies-of-polhemmarkdownavalonia).
- **Blazor themes that map the `--pmd-*` variables**: new variables for alerts, code tokens and math
  ([GitHub alerts](#github-alerts), [Highlighted code](#highlighted-code), [Math](#math)).

## New features and changes

### Mermaid diagrams

A ` ```mermaid ` block holding a flowchart (`flowchart` / `graph`, all four directions) or a sequence diagram is laid
out in `Polhem.Markdown` and drawn by both viewers, without a script. Text sizes are estimated from the characters, so
both viewers receive the same coordinates. Fallback is all or nothing: another diagram type, a statement outside the
subset (subgraphs, styles, loops, activation…) or a diagram above the limits (200 nodes, 400 links, 40 participants)
stays a code block. Diagrams are centered and scale down to the viewer's width. `MarkdownOptions.RenderMermaidDiagrams`,
`true` by default, turns it off.

Diagrams use the existing code background, rule and text colors; no variable is added.

### Highlighted code

Fenced code blocks are highlighted by the fence's language: C#, JSON, SQL, shell, PowerShell, JavaScript/TypeScript,
Python, XML/HTML, Razor, YAML and CSS. The scanners are written for this package, without regular expressions or a
dependency, and run in linear time. Indented blocks and unknown languages stay plain, as on GitHub.

- Avalonia: `CodeKeywordBrush`, `CodeStringBrush`, `CodeCommentBrush`, `CodeConstantBrush`, `CodeTagBrush` and
  `CodePropertyBrush`. Changing a brush recolors without a rebuild.
- Blazor: `--pmd-code-keyword`, `--pmd-code-string`, `--pmd-code-comment`, `--pmd-code-constant`, `--pmd-code-tag` and
  `--pmd-code-property`.

### Images

An image whose source, written or resolved against `BaseUri`, uses a scheme in `MarkdownOptions.AllowedImageSchemes`
(new, default `https`) is shown; any other shows its alternative text as before. `data:` URIs are not supported.

- Blazor writes `<img loading="lazy" referrerpolicy="no-referrer">`, scaled down to fit and never up.
- Avalonia shows the alternative text until the image loads, and for good if it fails. It loads `http`/`https` and
  `file` itself, at most 10 MB each, and caches per viewer; `MarkdownViewer.ImageLoader` (new) replaces the loader, for
  authentication, caching or a proxy.
- Avalonia draws an SVG only over `https` from a host in `MarkdownViewer.TrustedSvgHosts` (new; by default badge
  services such as `img.shields.io`) or a GitHub workflow badge, because a hostile SVG can exhaust the renderer
  ([ADR-001](../../../maintainers/adr/adr-001-svg-from-trusted-hosts.md)). Any other SVG shows its alternative text, so
  an SVG logo from a project's own site needs its host added. Blazor shows every allowed SVG through `<img>`, where its
  scripts do not run.

### Math

Math written as on GitHub — `$…$`, `` $`…`$ ``, `$$…$$` and ` ```math ` blocks — is rendered for a LaTeX subset:
fractions, roots, scripts, `\left … \right`, matrices and `cases`, `\text`, accents and spaces
([ADR-002](../../../maintainers/adr/adr-002-math-one-structure-two-layouts.md)). A single `$` next to a space opens or
closes nothing, so prices stay text. A formula outside the subset shows its source as code.

- Blazor writes MathML for the browser to lay out, with the font set by `--pmd-math-font` (new). Delimiters grow only
  with a font that has math tables.
- Avalonia lays the formula out with the viewer's font.

### Footnotes

Footnotes are numbered in the order a reader reaches them and listed at the end with back links. A reference to an
undefined note shows as written.

### GitHub alerts

A quote starting with `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` or `[!CAUTION]` becomes an alert with an icon
and an English title, as on GitHub. Any other marker stays an ordinary quote.

- Avalonia: `AlertNoteBrush`, `AlertTipBrush`, `AlertImportantBrush`, `AlertWarningBrush` and `AlertCautionBrush`.
- Blazor: `--pmd-alert-note`, `--pmd-alert-tip`, `--pmd-alert-important`, `--pmd-alert-warning` and
  `--pmd-alert-caution`.

### Raw HTML through an allowlist

The elements README files use become nodes of the model: `img`, `a`, `br`, `b`, `strong`, `i`, `em`, `code`, `sup`,
`sub`, `kbd`, `p` and `div` aligned center or right, `details` and `summary`, and `picture` with a `source` chosen by
color scheme. `href` and `src` go through the link and image policy. Any other element loses its tags and keeps its
content; the content of `script`, `style`, `iframe` and the like is dropped. No HTML reaches a viewer as markup.

Text that only looks like a tag (`List<string>`) and a tag that does not pair up within its paragraph show as written,
since prose names tags far more often than it leaves them open.

### Relative links and images

`MarkdownOptions.BaseUri` (new, an absolute URI) resolves relative links and images by the standard URI rules. The
result still goes through the scheme check. Without a base, relative links stay text.

### Links to headings and footnotes

Headings get the ids GitHub gives them, and a link to `#id` in the same text scrolls the viewer to that heading or
footnote. These links do not raise `LinkActivated` / `OnLinkActivated`. The Blazor viewer does not write the id as an
HTML `id`, so it cannot clash with the host page or a second viewer.

### Strikethrough, task lists, emoji and front matter

`~~text~~` is struck through; `- [ ]` and `- [x]` show check boxes, which both viewers now draw themselves with the
link and rule colors so they look the same everywhere. Emoji shortcodes such as `:smile:` become emoji. YAML front matter
at the start of the text is hidden.

### Bold CJK text in the Avalonia viewer

Bold CJK text in the Avalonia viewer could render regular, or make the rest of the line bold, because of how Avalonia
reuses fallback fonts. `MarkdownViewer.CjkFontFamily` (new, `null` by default) names the family to draw CJK text in, for
example `PingFang TC, Microsoft JhengHei UI, Noto Sans CJK TC`; the viewer then draws CJK stretches in it and loads its
heavier faces before drawing.

### `MarkdownEditor`

`Polhem.Markdown.Avalonia` adds `MarkdownEditor`, a Markdown source editor built on AvaloniaEdit's core
([#37](https://github.com/polhem-dev/polhem-markdown/issues/37)):

- Line numbers, word wrap, undo and redo, and search (Ctrl+F).
- Colouring of markers, headings, emphasis, code, links, URLs, raw HTML and formulas, with fenced code highlighted as
  in the viewers, using the same brush names.
- `ApplyFormat(MarkdownFormat)` applies or removes a format on the selection as one undo step. `MarkdownFormat` is a
  new enumeration in `Polhem.Markdown`: `Bold`, `Italic`, `Strikethrough`, `InlineCode`, `Link`, `Heading1` to
  `Heading3`, `BulletList`, `NumberedList`, `TaskList`, `Quote` and `CodeBlock`. Ctrl (Cmd on macOS) with B, I, K and
  E applies bold, italic, link and inline code.
- Enter continues a list, and on an empty item ends it; Tab and Shift+Tab change a list item's level.
- `Markdown` binds two-way. Links in the source cannot be opened from the editor, since that would bypass the scheme
  check.
- It brings its own theme resources, so it works under Fluent, Simple, Semi or any other host theme.

No AvaloniaEdit type is part of the public API.

### Keeping the editor and the viewer in step

- `MarkdownViewer.GetVerticalOffset(int)` and `GetSourceOffset(double)` map between a source offset and the viewer's
  vertical position.
- `MarkdownViewer.SourceRequested` is raised on a command-click (Ctrl, or Cmd on macOS); without a handler that handles
  it, a command-click does what it did before.
- `MarkdownEditor.FirstVisibleSourceOffset` and `ScrollToSourceOffset(int)` do the same on the editor side.

### Partial rebuilds in the Avalonia viewer

When `Markdown` changes, the Avalonia viewer now keeps the blocks that match from the start and from the end, and
rebuilds only those between. Inserting a paragraph at the top of a 66-block text went from 67 rebuilt blocks (25 ms) to
one (3 ms). Kept blocks keep their state, such as a selection or an expanded section. A reply that grows at the end
behaves as before.

## Changes in behaviour

### Images load by default

0.1.0 showed every image as its alternative text. Images from `https` now load, which tells the image's server the
text was viewed.

**What to do**: to keep the 0.1.0 behaviour, clear the set:

```csharp
options.AllowedImageSchemes.Clear();
```

### Allowed raw HTML renders

0.1.0 showed all raw HTML as the text it was written as. The allowed elements now render, other elements lose their
tags, and the content of `script`, `style` and the like is dropped. Nothing to do unless a host relied on seeing the
HTML source.

### A target without a scheme is a relative reference

Only a link target that writes its scheme counts as absolute. .NET reads a rooted path such as `/etc/passwd` as
`file:///etc/passwd`, so a host that allowed the `file` scheme used to get a link to a local file from it. Now it
resolves against `BaseUri` like any relative reference, and without a base it is text.

**What to do**: if `AllowedLinkSchemes` includes `file`, write `file:///…` to link to a local file.

### The Blazor viewer loads a module

The Blazor `MarkdownViewer` now implements `IAsyncDisposable` and loads a small module, `polhem-markdown.js`, the
first time an in-document link is clicked, to scroll to its target.

**What to do**: a page with a Content Security Policy must allow scripts from its own origin. Without the module the
click does nothing; nothing else depends on it.

### New dependencies of `Polhem.Markdown.Avalonia`

`Polhem.Markdown.Avalonia` now depends on:

- `Svg.Skia` 5.1.1, for SVG images. It is the last version on SkiaSharp 3, which Avalonia 12 uses. Under Native AOT it
  works, but `Svg.Model` reports a trim warning (IL2104) that an application treating warnings as errors needs to
  suppress.
- `Avalonia.AvaloniaEdit` 12.0.0, for the editor, its core only. An application that uses only the viewer gets the same
  Native AOT executable as before; without Native AOT it ships one more assembly, `AvaloniaEdit.dll` (about 630 KB),
  which is never loaded.

## Fixes

- Deeply nested inline syntax, such as about ten thousand unmatched `[` or twenty thousand `*` around a word,
  overflowed the stack and ended the process of any application showing it in a viewer. Inline nesting past 32 levels
  now shows the rest as its source text ([#41](https://github.com/polhem-dev/polhem-markdown/pull/41)).
- An unmatched `[` disappeared (`a [b c` showed as `a b c`); it now shows as written, as on GitHub.
- The Avalonia viewer cut off the last line of every code block.
