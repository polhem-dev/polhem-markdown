# Polhem.Markdown 0.4.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.4.0.md)

This file holds the details behind the `[0.4.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This version is about reading: a reader control with a table of contents, finding text, opening and saving images,
showing a reply while it still arrives, and selecting, copying and screen-reading text in the Avalonia viewer. Every
feature works the same way on both front ends, except where a browser already does the job itself.

No public member is removed or changed. What each kind of application has to look at:

- **Avalonia applications with keyboard users**: a paragraph without links is no longer a Tab stop, and Tab now stops
  at links ([Tab moves through links in the Avalonia viewer](#tab-moves-through-links-in-the-avalonia-viewer)).
- **Avalonia applications that bind Ctrl+F or F3 themselves**: the viewer handles these keys while it has the focus
  ([The Avalonia viewer handles Ctrl+F and F3](#the-avalonia-viewer-handles-ctrlf-and-f3)).
- **Blazor themes that map the `--pmd-*` variables**: four new variables
  ([New CSS variables](#new-css-variables-in-the-blazor-package)).
- **Code that reads the Avalonia viewer's selection or clipboard text**: copying now runs across blocks and turns
  images and formulas into text ([Selecting and copying across blocks](#selecting-and-copying-across-blocks)).

## New features

### `MarkdownReader` and the table of contents

Both packages add `MarkdownReader`, a control around a viewer that scrolls it in a centred column and offers a table of
contents ([#79](https://github.com/polhem-dev/polhem-markdown/issues/79)):

- A narrow rail along its edge has a line for each heading. Pointing at the rail or clicking it slides the list of
  headings out over the text; picking one scrolls it to the top and moves the focus there.
- `OutlinePinned` keeps the list beside the text as a column, and binds both ways, so a host can remember it.
  `OutlineSide` puts the rail and the list on the left or the right.
- The rail and the list mark the section being read.
- `TextMaxWidth` caps the width of the text column. `OutlineLabel`, `PinOutlineLabel` and `UnpinOutlineLabel` replace
  the English labels.
- The rail is a button and the list a navigation landmark for screen readers.

The viewers themselves list the text's headings (`Headings`, with `HeadingsChanged` on Avalonia and
`OnHeadingsChanged` on Blazor) and scroll one to the top of the view (`ScrollToHeading`, `ScrollToHeadingAsync`).
`MarkdownHeading` gives each heading's level, text, id and source offset, and the ids are the same on both front ends
([#71](https://github.com/polhem-dev/polhem-markdown/issues/71)). A host that draws its own table of contents uses
these instead of the reader.

### Finding text

On Avalonia, Ctrl+F (⌘F on macOS) opens a find bar at the top right of the viewer
([#85](https://github.com/polhem-dev/polhem-markdown/issues/85)). It finds as you type and highlights every match;
Enter and F3 go to the next match, Shift with either to the previous one, and Escape closes the bar. A match in a
closed `<details>` section opens it. The reader's rail has a search button, which is the way in on a phone or tablet.
`FindMatchBrush` and `FindCurrentMatchBrush` color the highlights, and `FindBarLabels` translates the bar.

In the browser, the browser's own find works on the viewer's text. Both viewers also have the same API, for a host
with a find box of its own: `Find`, `FindNext`, `FindPrevious` and `CloseFind` on Avalonia; `FindAsync`,
`FindNextAsync`, `FindPreviousAsync` and `ClearFindAsync` on Blazor, with `FindMatchCount` and `CurrentFindMatch` on
both. A match runs across emphasis and links and finds an image by its alternative text.

### Opening and saving images

With `ZoomImages` set, a click on an image or Enter opens it at full size over the window
([#72](https://github.com/polhem-dev/polhem-markdown/issues/72)). The wheel, a pinch or + and - zoom it, a drag pans
it, a double click switches between fitting the window and the image's own size, and Escape or a click beside it
closes it. An image inside a link opens the link instead. A host shows images its own way with `ImageActivated`
(Avalonia) or `OnImageActivated` (Blazor).

The open image has a toolbar at its top right with a save button beside the close button
([#88](https://github.com/polhem-dev/polhem-markdown/issues/88)). It saves the original file: Avalonia through a save
dialog, Blazor as a download. When the image's server does not let the page read it, the Blazor viewer opens the image
in a new tab, where the browser saves it. A host saves images its own way with `ImageSaveRequested` (Avalonia) or
`OnImageSaveRequested` (Blazor).

### Showing a reply while it arrives

`IsStreaming`, on both viewers, tells the viewer that the text is a reply still arriving
([#69](https://github.com/polhem-dev/polhem-markdown/issues/69)). While it is set, the syntax the last block leaves
open is closed or held back: bold and inline code are closed, a link or an image shows once its address is complete,
and a table shows once its header row is. Markers, partial addresses and lines of pipes no longer show and then jump.
Set it back to `false` when the reply is complete, and the text shows exactly as written.

The Blazor viewer now renders only the top-level blocks a change of the text affects, as the Avalonia viewer already
rebuilt only those: a reply that grows renders its last blocks, and an edit the blocks it touches. It used to render
the whole text on every change.

### Selecting and copying across blocks

The Avalonia viewer selects text across blocks, as a browser does
([#1](https://github.com/polhem-dev/polhem-markdown/issues/1)). A drag runs from one paragraph, list item, table cell
or code block into the next and scrolls at the edge of the view, Ctrl+A (⌘A) selects the whole text, and copying
gives plain text in document order. An image is copied as its alternative text and a formula as its LaTeX (`$…$`).

On Avalonia 12.0, copied text no longer loses or shifts characters after an image or a formula, and a triple click
selects such a paragraph to its end.

### Screen readers in the Avalonia viewer

The Avalonia viewer tells screen readers what the Blazor viewer's HTML does
([#70](https://github.com/polhem-dev/polhem-markdown/issues/70)): headings with their level, links, lists and list
items, tables, images by their alternative text, and alerts, quotes and collapsible sections as named groups. The
Blazor viewer marks an alert with `role="note"`, as the Avalonia viewer names it.

## Changes in behaviour

### Tab moves through links in the Avalonia viewer

Tab now moves through the links and buttons of the text in the order of the text, and Enter follows a link. A
paragraph without links is no longer a Tab stop; a click still gives it the focus for selecting and copying.

**What to do**: nothing, unless your application relies on Tab reaching every paragraph.

### The Avalonia viewer handles Ctrl+F and F3

While the focus is in the viewer, Ctrl+F (⌘F) opens its find bar and F3 steps through matches; the viewer marks these
keys handled, so a key binding of the window no longer sees them there.

**What to do**: an application with a find of its own calls the viewer's `Find` API from it, or handles the keys in a
tunnelling handler before they reach the viewer.

### Fixes in the Avalonia viewer

- A click on an image inside a link opens the link. It used to do nothing.
- A heading or footnote the viewer moves the focus to stays at the top of the view. The scroll viewer used to move it
  out of place again as it brought the focused text into view.
- Moving to a heading or a footnote above the view, in a scroll viewer shorter than the window, scrolls it to the top
  of the view. It used to leave it above the view by the difference.

### New CSS variables in the Blazor package

| Variable | Default | Used for |
|----------|---------|----------|
| `--pmd-zoom-backdrop` | `rgba(16, 16, 16, 0.9)` | the backdrop of an image opened at full size |
| `--pmd-find` | `rgba(255, 213, 0, 0.4)` | the highlight of every match |
| `--pmd-find-current` | `rgba(255, 150, 50, 0.8)` | the highlight of the current match |
| `--pmd-outline-bg` | `Canvas` | the background of the reader's table of contents, which must hide the text under it |

**What to do**: a theme that maps the `--pmd-*` variables to its own colors adds these four.
